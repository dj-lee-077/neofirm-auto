## 2. 완전 자동이 깨진 지점
| 문제 | 증상 | 원인 | 사람이 한 일 | 다음에 막는 법 |
|---|---|---|---|---|
| 소스 50개 한도 | `source add` 실패, rpc_code=9 | S5에서 소스를 한도까지 채움 | 소스 삭제 (1개 오삭제) | S5 소스를 35~40개로 제한해 S12 여유 슬롯 확보 |
| 쿠키 만료 | `CSRF token not found` | 세션 쿠키 무효화 | 쿠키 재발급 (여러 차례) | 단계 전 인증 확인, 시작 전 사전 점검 |
| 계정·세션 불일치 의심 | 웹 UI 45개 / CLI 50개 | CLI 쿠키 계정이 브라우저와 다른 것으로 의심 | 쿠키 재발급 | 같은 계정 쿠키 사용 확인 |
| 슬라이드 생성 rate limit | `RateLimitError` 4회, 빈 아티팩트 4개 | 생성 쿼터 소진 추정 | 시간 두고 재실행 | 긴 간격 자동 재시도, 실패 시 빈 아티팩트 정리 |

## 3. 비교: CLI vs 다른 방식
- 같은 과제를 다른 채팅에서 NotebookLM CLI가 아닌 방식(NotebookLM 직접 연동)으로 했을 때는 완전 자동이 됐다고 한다. 이번 CLI 방식에서 막힌 지점은 모두 인증·한도·쿼터 문제였다.
- 아직 확인하지 않은 것: 그 방식이 어떤 연동인지, 같은 소스 수와 슬라이드 생성에서 한도에 걸리지 않았는지. 정리할 때 채울 것.
